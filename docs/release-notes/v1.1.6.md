## Highlights

- **Faster Windows VMs under WHPX.** Native Windows guests now run with `-cpu host` instead of the minimal `qemu64` model, so they see the host CPU and its instruction set extensions (SSE4.x, AES-NI, POPCNT and more) rather than a 2003-era baseline. CPU-bound work such as compression, crypto, compilers and package installs is much faster. XSAVE stays masked (`-cpu host,-xsave`, guest `noxsave`) because WHPX cannot run it reliably, so AVX is not available to the guest.
- **Hypervisor Platform detection without administrator rights.** Before probing WHPX, pvm now checks that Windows Hypervisor Platform is enabled and its hypervisor is running, by querying `WHvGetCapability` from `WinHvPlatform.dll`. Unlike `Get-WindowsOptionalFeature`, this works for a standard user, so a per-user install does not wrongly fall back to TCG. `PVM_QEMU_ACCEL=whpx` still forces a WHPX attempt.
- **Windows installers.** Releases ship per-user `pvm_windows_amd64_setup.msi` and `pvm_windows_amd64_setup.exe`. Neither needs administrator rights. Both install `pvm.exe` to `%LOCALAPPDATA%\pvm`, add it to the user `PATH`, include the bundled QEMU runtime, and uninstall from Settings > Apps while keeping VM data under `~/.pvm`. When run interactively, both offer to stop a running pvm before replacing files. See [Windows installers](https://github.com/BitterOrange/pvm#windows-installers) for details and known limitations.

## Also in this release

Merged from upstream v1.1.5:

- `create`, `start`, `clone` and `image build` print backend-specific acceleration guidance when they fall back to TCG; set `PVM_QEMU_ACCEL=tcg` to silence it.
- SSH to the managed gateway waits up to 10 seconds to connect, up from 5.
- `pvm compact` works with QEMU before 11, which names the `qemu-img convert` backing option `-B` instead of `-b`.
- When forwarding to WSL from Git Bash, guest paths that Git Bash rewrote into Windows paths (such as `/tmp` turned into `C:/Program Files/Git/tmp`) are restored.
- `pvm image build` accepts options after the image name, for example `pvm image build ubuntu:26.04 --keep-vm`.

Development: the full `go test ./...` suite is written for Unix and should not be run on a Windows host. Run targeted tests there, and use Linux or macOS (CI or WSL2) for the full suite.
