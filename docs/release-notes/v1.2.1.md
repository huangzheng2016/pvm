## Highlights

- **Better app windows.** GTK applications start in about a second instead of waiting for the desktop portal timeout. Apps can play sound on the host (`--audio off|out|both`, default `out`), file clipboard works in both directions on Windows, emoji input no longer disconnects the Xpra client, and Noto fonts cover more scripts and color emoji. Host window frames and app shutdown on VM stop are also improved.
- **More reliable Windows startup.** When Windows reserves a previously stored QEMU port, pvm picks a fresh loopback endpoint instead of failing to start the VM or its gateway. Endpoint files are replaced atomically and refresh errors are returned to the caller. A socket bind failure no longer falls back to TCG as if the accelerator were at fault.
- **App lifecycle and compatibility.** Existing CLI VM naming, clipboard/drop defaults, macOS UID handling, Xpra secret persistence, and app stop behavior are preserved. This release does not include PVM Desktop GUI, default-VM behavior changes, an app catalog, or an empty-password Secret Service keyring.

## Build and validation

- A native Windows CI job now vets, builds, and runs the packages and targeted tests that work on Windows. Tagged packages wait for it.
- The generated guest asset manifest is no longer tracked in Git; `cmd/assetpack` recreates it on every build, including clean checkouts.
- The Windows Xpra client retains its pinned SHA256 and signature checks and includes the surrogate-pair keyboard fix. NSIS and wixl installers were built with it.
- Full Go tests, vet, Windows cross-builds, endpoint refresh and write-failure tests, real macOS VM app lifecycle checks, and legacy desktop compatibility checks passed. Windows installation and WHPX runtime were not tested on a Windows host in this review.
