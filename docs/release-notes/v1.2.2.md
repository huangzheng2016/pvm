## Highlights

- **Sound in `pvm app`.** VM programs play through the host's default output. `pvm app config <vm> --audio off|out|both` sets it per VM: `out` is the default, `both` also lends the host's default microphone to the VM while a client is attached, and `off` turns sound off. The VM's apps now reach the Xpra server's PulseAudio instead of the session's own, which only had a null sink.
- **Copied files on the clipboard, both ways, on Windows hosts.** Files and folders copied in Explorer paste into Thunar, file dialogs, browsers and Electron apps in the VM, and files copied in the VM paste into Explorer. They go as a tar of at most 256 MB; links, names Windows refuses and paths leaving the folder are skipped and reported. The `--clipboard` setting decides each direction, as for text and images.
- **Emoji input.** The Windows Xpra client sent an emoji as two halves, failed to encode them and dropped the connection with every window. The installers now add a patch to the client that joins the halves into one character.
- **GTK apps open in about a second.** gedit, Thunar and other GTK programs waited 50 to 60 seconds for xdg-desktop-portal, which could not start without `DISPLAY`. The app display now sets it for D-Bus activated services.

## Fixes

- **`pvm stop` and `pvm rm` close app windows.** They stop the VM's Xpra server first, so the host client exits instead of leaving windows that keep trying to reconnect.
- **Fonts and sound for existing VMs.** VMs made before v1.2.1 get the Noto fonts, color emoji and the Xpra sound server on their next `pvm app`; restart running apps to use the new fonts.

## Upgrading

- The emoji patch is in the Xpra client of the Windows installers; reinstall with this release's installer.
- Sound and the file clipboard live in the host client; run `pvm app attach <vm>` again after upgrading.
- Sound is on and the microphone off by default; `pvm app config <vm> --audio off` turns sound off.

## CI

- A `windows` job vets, builds and runs the packages whose tests pass on Windows, and tagged releases wait for it. The packages still failing on Windows are listed in [docs/roadmap.md](../roadmap.md).
