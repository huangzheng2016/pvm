## Highlights

- **Workspaces.** `pvm workspace` binds one host folder to one VM at `/workspace/<id>`, with `~/workspace` linked to `/workspace` in the VM. Pick a mode at `create`:
  - `mount`: one shared copy. Linux, macOS and WSL2 use 9p. The native Windows backend uses reverse sshfs: the VM runs a passive sshfs and pvm serves SFTP over the existing SSH session, confined to the folder. Mounts come back after the VM restarts or the session drops. Windows keeps no exec bit, so the VM sees ELF files and scripts starting with `#!` as 755 and other files as 644.
  - `sync`: a copy on each side. `push` and `pull` use a three-way check against the last baseline and write nothing on a conflict until you pass `--prefer host|vm` or `--keep-both`.
  - `copy`: upload once, work in the VM, then download the result with `clone`.

  Uploads skip `.gitignore` matches and `node_modules`, and `.pvmignore` adds or re-includes paths. pvm refuses to upload or mount the home directory, a file system root or credential directories such as `.ssh`. `rm` never deletes host files. See [Workspaces](../../README.md#workspaces) and the [design](../design/workspace.md).
- **Firefox and sshfs in golden images.** Firefox comes from Mozilla's APT repository on Ubuntu and Debian, not the snap: the bake checks the signing key fingerprint and pins the repository so Ubuntu's snap transitional package cannot win. Only images baked from this release on include them; run `pvm image build` to rebake.
- **Faster bakes.** The provision script downloads packages eight at a time and checks each against the signed index before apt uses it. A package that fails to download is left to apt.
- **Bakes no longer hang.** The bake VM first boots with the `qemu64` CPU model and then cold boots, SSH sessions use keepalives, a guest kernel panic fails the bake, and stalled downloads time out.
- **`pvm rm` of a VM whose files were deleted by hand.** Deleting `~/.pvm/vms/<name>` left the VM as a cluster member, kept the daemon unready and made `pvm rm` answer "not found". The daemon now logs the orphan and stays ready, and `pvm rm` drops its membership, port maps, relays and gateway link. It refuses while a QEMU process may still use the VM's address.

## Documentation

- The exit setup lists the ports the exit agent needs and the ufw rules for its TUN devices. A firewall that drops forwarded traffic lets `pvm exit test` pass while VMs cannot connect.
- On the native Windows backend, use `--transport tcp` for exits: a UDP exit may never complete its handshake from the gateway VM.

## Build

- A pvm built with plain `go build` has no guest assets; its daemon now says to build with `script/build.sh`. `PVM_OUT` writes the binary to another path.
