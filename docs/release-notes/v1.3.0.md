## Highlights

- **PVM Desktop.** A window for the common paths on native Windows (WHPX), in the spirit of Docker Desktop. Both Windows installers ship `pvm-desktop.exe` with a Start menu shortcut. It shows each VM's state and startup stage; starts, stops and deletes VMs; opens a terminal, an app or the VM's file manager as host windows; creates VMs with their size, exit, clipboard, drop and audio settings and programs to preinstall; manages exits, the default exit and each VM's exit; manages workspaces and opens a terminal, an app or the file manager in the matching guest folder; and sets the default VM and what starts at sign-in. The window reads in English or Simplified Chinese, follows the system's light or dark theme, and shows VMs as rows or cards. Every change runs `pvm.exe`, whose output shows in the Activity panel. See [docs/design/gui.md](../design/gui.md).
- **A stored default VM.** `pvm default-vm <vm>` records a VM that commands use when none is named and the current folder is in no workspace; `pvm default-vm --clear` removes it. A default VM that was deleted is an error, never a silent fallback to another VM.
- **Readiness in `pvm ls`.** The STATUS column reads stopped, starting with the current stage, ready or failed, and `GET /v1/vms` carries the same.
- **Built-in apps.** `pvm app catalog` lists programs pvm can install, and `pvm app install <vm> <id>...` installs them inside the VM: Claude Code, Claude Desktop and Codex CLI. Downloads run in the VM and leave through its exit. Run inside a workspace, `pvm app` starts the program in the matching guest folder, as `pvm ssh` does.
- **App windows unlock the keyring.** The app display has no desktop sign-in, so gnome-keyring asked for a password whenever a program stored a secret. When the Xpra server starts, a `login` keyring with an empty password is created if missing and unlocked; keyrings with a password are left alone. See SECURITY.md.

## Fixes

- **VMs start after Windows reserves their ports.** Each VM's QEMU listens on loopback ports stored on first use. A reboot can make Windows reserve a range covering them; QEMU then failed to bind, the gateway did not start and no VM of its cluster could. Ports that can no longer be bound are now replaced before a VM or gateway starts, and a bind failure no longer falls back to TCG and blames the accelerator.
- **Terminals of a VM open in its home directory.** PVM Desktop's terminal of a VM inherited the app's working directory, so it could start in a workspace folder.
- **CI on macOS.** A desktop test compared a symlinked temporary path with its resolved form, and a tunnel test required one particular TCP connection where a reconnect is as good; both are fixed, the second taken from upstream.

## Upgrading

- Install with this release's installer to get PVM Desktop; `pvm upgrade` replaces `pvm.exe` only.
- The new VM list fields come from the daemon: restart it after upgrading (`pvm daemon restart`), which stops running VMs.
